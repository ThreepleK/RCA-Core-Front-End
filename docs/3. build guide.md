# 디버깅
  - 개별 수동 개발
  ```
  > pnpm --filter host dev
  > pnpm --filter rca dev
  > pnpm --filter dashboard dev
  ```

  - 개별 수동 빌드
  ```
  > pnpm --filter host build
  > pnpm --filter rca build
  > pnpm --filter dashboard build
  ```

  - 개별 수동 정리
  ```
  > pnpm --filter host clean
  > pnpm --filter rca clean
  > pnpm --filter dashboard clean
  ```

  - 전체 패키지 정리 및 패키지 새로 설치
  ```
  > sh ./clean.sh
  ```

# 권장
  - 전체 개발 만
  ```
  > pnpm dev
  ```

  - 전체 빌드 만
  ```
  > pnpm build
  ```

# 배포
  + __[Type A]__ 배포를 위한 빌드 (컨테이너 1개 이면서, 같은 도메인 내 구성 빌드)
    - sh ./prod-build-single.sh
      * 배포 소스(raw)는 아래와 같습니다
      ```
          /docker-compose/single/dist
            └ dist
              ├ assets
              ├ r
              │  ├ rca
              │  ├ dashboard
              │  ├ ...
              │  └ etc ..
              ├ mf-manifest.json
              └ index.html
      ```
      * 1개의 도메인 에서 처럼 구동하는게 목표
      * docker가 켜져 있다면 배포와 동시에 로컬 서버가 구동 됩니다.

  <br />

  + __[Type B]__ 배포를 위한 빌드 (컨테이너 여러개 이면서, 다른 포트 구성 빌드)
    - sh ./prod-build-remote.sh
      * 배포 소스(raw)는 아래와 같습니다
      ```
          /docker-compose/remote/dist
            └ dist
              ├ app
              │  ├ assets
              │  ├ mf-manifest.json
              │  └ index.html
              └ r
                  ├ rca
                  ├ dashboard
                  ├ ...
                  └ etc ..
      ```
      * 여러개의 도메인에서 구동하는게 목표
        · 메인 도메인: /dist/app
        · 기타 도메인: r/*
        · 메인에서 기타를 호출 할 때 nginx의 proxy_pass로 연결하는 방식
      * docker가 켜져 있다면 배포와 동시에 로컬 서버가 구동 됩니다.


* __!! 배포는 2가지를 하는게 아닌 A, B중에 원하는 것으로 배포하시면 됩니다. !!__
