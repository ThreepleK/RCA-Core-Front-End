# router는 아래와 같은 파일에 영항을 받습니다.
  ```
  - apps
    ├ Host
    │  ├ vite.config.ts
    │  └ src
    │    └ router
    │      └ index.tsx
    ├ App 1
    │  ├ vite.config.ts
    │  └ src
    │    └ router
    │      └ index.tsx
    └ App 2
       ├ vite.config.ts
       └ src
         └ router
           └ index.tsx

  - packages
    └ env
      └ env-common.ts

  - docker-compose
    └ remote
      ├ dist
      │  ├ Host
      │  ├ App 1
      │  └ App 2
      ├ docker-compose.yml
      └ nginx.conf

  ```

  |No|대상 파일|설명|
  |----|----|----|
  |1|/apps/*/src/router/index.tsx|각 앱의 라우터 설정 값|
  |2|/packages/env/env-common.ts|Host ↔ App간의 MF 연결을 위한 도메인 설정 값|
  |3|/apps/*/vite.config.ts|각 앱의 base가 될 라우터 값|
  |4|/docker-compose/remote/*|배포 proxy 설정|
  * MF: Model federation

<br /><br />

# App router 설정 방법
  1. apps/app 1/src/router/index.ts
  ```ts
    import { createBrowserRouter } from 'react-router-dom';
    import type { RouteObject } from 'react-router-dom';
    import { lazy } from 'react'

    // 메인 메뉴 모음
    const Main = {
        Root: lazy(() => import('@/features/main')),
        Test: lazy(() => import('@/features/test')),
    };

    //* 라우터 내역
    const routeList: RouteObject[] = [
        {
            path: '/',
            children: [
                { path: '/', element: <Main.Root /> },
                { path: '/test', element: <Main.Test /> },
            ]
        },
    ];

    export const router = createBrowserRouter(routeList, {
        basename: '/app1'   // 기본 도메인 주소
    });
  ```
  * 여기서 중요한 부분은 <span style='color:#39f'>__원하는데로 라우터를 설정하되__</span><br />
    기본 도메인 주소가 될 __basename은__ 꼭 앱 이름에 맞게 설정해주세요.

  * <span style='color:#fd3'>__basename은 이제__</span> 추가 설정 할 항목과 <span style='color:#f39'>__꼭 맞춰야 합니다.__</span>

  * 지금 부터 __예시는 /app1을__ 기준으로 설명합니다.

  <br />

  2. /packages/env/env-common.ts
  ```ts
    // 개발 주소
    const _DEV_HOST = 'http://localhost';
    // 운영 주소
    const _PROD_HOST = 'http://localhost';
    // 운영에서 사용 될 원격 기본 주소
    const _PROD_HOST_REMOTE = `${_PROD_HOST}/r`;

    export default {
        //* 메인 앱 개발/배포 주소
        mainAppHost: {
            development: `${_DEV_HOST}:5000`,
            production: `${_PROD_HOST}`,
        },

        //* 원격 앱 연결 키 값
        remoteAccessKey: {
            ...
            app1: 'app1'    // ← 추가 1
        },

        //* 원격 앱 개발/배포 주소
        remoteAppHost: {
            development: {
                ...
                app1: `${_DEV_HOST}:5009`, // ← 추가 2
            },
            production: {
                ...
                app1: `${_PROD_HOST_REMOTE}/app1`, // ← 추가 3
            }
        },

        //* 원격 앱 연결 파일 명 (Module federation)
        mf_fileName: 'remoteEntry.js',

        //* 연결 시 사용 될 항목 (각 앱 경로 기준)
        exposeSync: {
            ...
            app1: { './main': './src/App.tsx' },  // ← 추가 4
        }
    }
  ```

  |추가|경로|설명|
  |----|----|----|
  |추가 1|remoteAccessKey|App을 연결 하기 위한 키 값<br />(특수한 경우가 아니라면 키와 값을 동일하게 맞춰주세요)|
  |추가 2|remoteAppHost.development|App 개발 주소<br />(개발 환경에서 Host에서 App1을 접속하기 위한 주소가 됩니다.)|
  |추가 3|remoteAppHost.production|App 배포 주소<br />(운영 환경에서 Host에서 App1을 접속하기 위한 주소가 됩니다.)|
  |추가 4|exposeSync|Host에서 App의 연결할 모듈을 설정합니다.<br />(host에서는 /app1/main을 호출하여, App.tsx의 파일의 기능을 사용할 수 있습니다.)|

  주석의 추가 1 ~ 4까지의 내용을 적용 합니다.
  
  * remoteAccessKey 키 값과, exposeSync의 키는 동일해야 합니다. (app1)

  <br />

  3. /apps/*/vite.config.ts
  ```ts
    import path from 'path'
    import { defineConfig } from 'vite'
    import react from '@vitejs/plugin-react-swc'
    import { federation } from '@module-federation/vite';
    import envs from '../../packages/env/env-common';

    /** @type {import('vite').UserConfig} */
    export default defineConfig((({ mode }: any) => {
      const remote = (envs.remoteAppHost as any)[mode];
      const accKey = envs.remoteAccessKey.app1;
      const exposes = envs.exposeSync.app1;
      const filename = envs.mf_fileName;

      return {
        ...
        define: { '$resourceUrl': JSON.stringify(remote.app1) },
        base: `${remote.app1}`,
        plugins: [
          ...
          federation({
            name: accKey,
            filename,
            exposes,
            shared: {
              react: { singleton: true }
            }
          }),
        ],
        server: { port: 5009, },
        ...
      };
    }))

  ``` 

  |설정 명|설명|
  |----|----|
  |define|리소스 관리를 위한 App 상수설정<br />(상세 내용이 필요하다면 [관련문서 이동](./4.%20resource%20guide.md))|
  |base|App 기본 주소 설정|
  |plugins|App 관련 플러그인 설정<br />(* 여기서는 MF사용을 위해 코드와 같이 적용합니다.)|
  |server|개발 환경에서 사용될 App 서버 설정<br />(* 여기서는 env-common.ts에서 적용한 포트를 동일하게 맞춰줍니다.)|

  2. /packages/env/env-common.ts 에서 설정한 내용을 위 코드와 같이 적용하고,<br />
  __server.port도__ 동일하게 맞춰야 합니다. __(5009)__


  <br />

  4. /docker-compose/remote/nginx.conf
  ```
    events {}

    http {
        include       /etc/nginx/mime.types;
        default_type  application/octet-stream;

        # Upstream app1
        upstream app1 {
            server app1:80;
        }

        server {
            listen 80;

            # 프론트엔드 정적 파일 서빙
            location / {
                root /usr/share/nginx/html;
                index index.html;
                try_files $uri /index.html;
            }

            # proxy location app1
            location /r/app1/ {
                add_header Access-Control-Allow-Origin * always;
                add_header Access-Control-Allow-Methods "GET, POST, OPTIONS, PUT, DELETE" always;
                add_header Access-Control-Allow-Headers "Origin, X-Requested-With, Content-Type, Accept, Authorization" always;

                if ($request_method = OPTIONS) {
                    add_header Content-Length 0;
                    add_header Content-Type text/javascript;
                    return 204;
                }

                # Proxy pass
                proxy_pass http://app1/;
                proxy_set_header Host $host;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
            }
        }
    }

  ```

  |설정 항목|설명|
  |----|----|
  |# Upstream app1|Proxy pass에 사용될 docker container 주소 설정|
  |# Proxy location app1|실제 해당 App을 접근 할 때 사용될 주소<br />/packages/env/env-common.ts의 __remoteAppHost.production__ 과 동일해야 합니다.|
  |# Proxy pass|실제 적용할 Proxy 주소|

  여기서 하고자 하는 내용은 __http://localhost/r/app1__ 도메인으로 접근 하면<br />
  서버 내 컨테이너인 <span style="color:#f39">__//app1:80__</span>로 연결 하기 위한 설정 입니다.

  <span style="color:#f39">__(* 중요)__</span> packages/env/env-common.ts의 <span style="color:#fd3">__remoteAppHost.production__</span> 과 동일해야 합니다.

  <br />

  5. /docker-compose/remote/docker-compose.yml
  ```yml
    version: '3.9'

    services:
      host:
        build:
          context: .
          dockerfile: ./dockerfile-host
        container_name: host
        ports:
          - "80:80"
        depends_on:
          - app1

      app1:
        build:
          context: .
          dockerfile: ./dockerfile-remote
        args:
          DIST_PATH: ./dist/r/app1
        container_name: app1
        ports:
          - "5009:80"
  ```
  services에 app1을 위 코드와 같이 추가해 주세요.

  |설정 키워드|설명|
  |----|----|
  |services > host > depends_on|Host 서비스의 종속 성으로 app1을 추가합니다|
  |app1 > build|app1을 컨테이너로 동작하기 위한 dockerfile 빌드 설정|
  |app1 > args|dockerfile 빌드 시 필요한 인자 값|
  |app1 > args > DIST_PATH|app1의 빌드 결과 파일이 있는 경로|
  |app1 > container_name|Docker에서 사용될 컨테이너 이름|
  |app1 > ports|app1의 포트 설정|

  여기까지 적용 하였다면, 개발/배포 환경까지 설정이 끝났습니다.<br />

# Host router 설정 방법

  1. /apps/host/vite.config.ts
  ```ts
    import path from 'path'
    import { defineConfig } from 'vite'
    import react from '@vitejs/plugin-react-swc'
    import tailwindcss from '@tailwindcss/vite'
    import { federation } from '@module-federation/vite';
    import envs from '../../packages/env/env-common';

    // https://vite.dev/config/
    export default defineConfig((({ mode }: any) => {
      const remote = (envs.remoteAppHost as any)[mode];
      const accKey = envs.remoteAccessKey;
      const filename = envs.mf_fileName;
    
      const remotes: any = {};

      //* App 1
      remotes[accKey.app1] = {
        type: "module",
        name: accKey.app1,
        entry: `${remote.app1}/${filename}`,
        shareScope: 'default'
      };
    
      return {
        publicDir: path.resolve(__dirname, './public'),
        build: {
          target: 'chrome89',
        },    
        plugins: [
          federation({
            name: 'vite_provider',
            manifest: true,
            remotes,
            shared: {
              react: { singleton: true },
            },
          }),
          react(),
          tailwindcss(),
        ],
        server: {
          port: 5000
        },
        resolve: {
          alias: {
            '@': path.resolve(__dirname, './src')
          },
        }
      };
    }))
  ```

  위에서 /packages/env/env-common.ts의 내용을 추가하였기 때문에<br />
  아래와 같이 App 1 구간을 추가 하면 됩니다.
  ```ts
    //* App 1
    remotes[accKey.app1] = {
      type: "module",
      name: accKey.app1,
      entry: `${remote.app1}/${filename}`,
      shareScope: 'default'
    };
  ```

  <br />

  2. /apps/host/src/router/index.tsx
  ```tsx
    // 메인 메뉴 모음
    const Main = {
        ...
        // @ts-ignore
        App1: lazy(() => import('app1/main')),
    };

    //* 라우터 내역
    const routeList: RouteObject[] = [
        {
            path: '/',
            element: <Layout />,
            children: [
                ...
                { path: '/app1/*', element: <Main.App1 /> },
            ]
        },
        ...
    ];
  ```
  여기서 중요한 항목은 import와 path을 설정하는 부분 입니다.<br />

  path는 코드와 같이 __/app1/*__ 과 같이 적용하고

  import에서 사용되는 경로는<br />
  /packages/env/env-common.ts의 exposeSync에 설정한 내용을 기준으로 적용합니다.<br /><br />

  ```ts
    // ex A
    exposeSync: {
      app1: { './main': './src/App.tsx' }
    }
  ```
  ex A와 같다면 app1/main을 사용할 수 있고,

  ```ts
    // ex B
    exposeSync: {
      app1: { './test': './src/App.tsx' }
    }
  ```
  ex B와 같다면 app1/test을 사용할 수 있습니다.

  여기까지 진행되었다면 router 설정은 끝이 납니다.
